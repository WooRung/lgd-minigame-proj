# Cloudflare 배포와 운영 인계

2026-09-09 사용자의 실제 배포 승인 후 Cloudflare Free에 첫 배포했다. 공개 주소는 [틈새 오락실](https://teumsae-arcade.ys-475.workers.dev)이다. 이 문서는 배포 상태와 후속 운영 절차를 기록한다. 단계별 증거는 [PLAN.md](PLAN.md), 게임 규칙은 [PROJECT.md](PROJECT.md)에 있다.

## 승인과 준비 상태

- 정적 웹·HTTP API·실시간 방을 하나의 Worker에 배포하고 D1을 연결한다. 같은 출처를 사용하며 최초 주소는 `workers.dev`를 권장한다.
- 이번 첫 배포는 사용자의 “오케이 이제 배포 하자” 승인으로 실행했다. 로그인된 단일 계정의 Workers 현재 요금제가 무료임을 대시보드에서 확인했고, 동명 Worker와 기존 D1이 없음을 조회한 뒤 생성했다. 후속 배포/원격 SQL은 해당 변경의 승인을 받은 뒤 수행한다.
- CI, GitHub 자동 배포, 유료 플랜 전환, 도메인/계정/결제 변경은 이 안내를 실행하는 것만으로 승인되지 않는다.
- `wrangler.jsonc`에 실제 계정 ID와 D1 ID를 반영했다. 이 ID들은 자격증명이 아니다. `dist/`의 생성 설정은 직접 편집하지 않는다. Vite의 `remoteBindings: false`를 유지하여 로컬 개발은 로컬 D1을 사용한다. `preview_database_id`는 배포 전부터 사용한 로컬 식별자 `00000000-0000-0000-0000-000000000000`으로 고정해 기존 로컬 기록을 보존한다. 이 값은 원격 미리보기 DB가 아니므로 `--remote --preview`에는 사용하지 않는다.
- 앱 자체의 고정 세션 시크릿이나 외부 API 키는 필요 없다. 서버가 난수 세션을 만들고 해시만 D1에 저장한다. Cloudflare 인증 정보는 Wrangler 로그인 또는 안전한 자격증명 경로로 제공하며 문서·채팅·로그·Git에 넣지 않는다.

## 공개 서비스 검증 재현

공개 DB에 실제 플레이 기록을 남기는 별도 명령이다. 배포 검증이 승인된 때만 실행한다. 일반 `npm run test:e2e`는 계속 로컬 전용이다.

```sh
ARCADE_REMOTE_VERIFY=1 npx playwright test --config playwright.remote.config.ts
```

이 설정은 실제 UI 플레이 시나리오 10개만 선택하며 로컬 서버를 실행하지 않는다. 합성 점수·부하·DB fixture 검증을 포함하지 않으며, 인증 정보가 남을 수 있는 trace/video 수집을 끈다. 러너 대전 조회는 테스트의 baseURL을 사용해 로컬/원격을 혼용하지 않는다. 검증 플레이어의 기록도 일반 기록으로 남으며 임의로 원격 SQL 삭제하지 않는다.

기본 브라우저 8개/6.1분, 15초 재접속 유예 만료·종료 틱 정지·빈 방 정리 1개/26.8초, 두 게임 일간·주간 실제 플레이와 랭킹 복귀 1개/약 1.2분이 통과했다. 도전 후 선택 기간이 초기화되는 화면 문제를 수정하고 해당 흐름을 로컬과 수정 버전 공개 URL에서 다시 검증했다. 게임 코어/통신이 바뀌지 않은 이전 통과 항목은 반복하지 않았다. 세션 Secure·HttpOnly·SameSite=Strict, 기록 저장, 별도 2인/4인 프로필의 실제 입력·재접속·관전·재대결을 포함한다. 자세한 증거는 PLAN D1에 기록했다.

최종 통합 브라우저 4개(저장 응답 유실·화면 이탈·작은 화면·요청 제한·소켓/빈 방 정리·퇴장 장애 복귀), 타입·Biome, 프로덕션 빌드와 `wrangler deploy --dry-run`이 통과했다. 배포 번들은 Worker 58.09KiB(gzip 16.99KiB), 정적 에셋 9개이며 DB/ROOMS 바인딩을 확인했다. Phaser 별도 청크 약 1.20MB(gzip 319KB) 경고는 남아 있고 게임 선택 시 지연 로드한다. 경고를 끄거나 검사 기준을 낮추지 않았다. 이 문단은 개선 Goal 종료 시 로컬 증거다. 이후 공개 검증과 원격 사용량 증거는 PLAN D1과 아래 첫 배포 측정을 따른다.

## 1. 로컬 준비 재현

검증 환경은 Node.js 24.16과 npm이다. 저장소의 lockfile 버전을 그대로 사용한다.

```sh
npm ci
npm run db:local
npx playwright install chromium
npm run typecheck
npm run check
npm run test
npm run test:e2e
npm run deploy:check
```

브라우저 검증은 로컬 개발 서버를 자동으로 실행하거나 이미 실행한 `http://127.0.0.1:5173`을 사용한다. 5단계 완주·실제 경주·재접속 유예를 실제 시간으로 확인하므로 전체 검증에는 수 분이 걸린다. 코드 변경 후에는 해당 기능 파일의 표적 검증을 사용한다. `deploy:check`는 Vite 빌드와 Wrangler `--dry-run`이다. 인증·원격 DB·공개 URL의 동작은 이 결과만으로 증명되지 않는다.

## 2. 원격 리소스 준비 — 승인 후에만 실행

아래는 이번 첫 배포에서 실행한 절차다. 재배포 때 DB를 다시 생성하지 않는다. 사용할 Cloudflare 계정과 기존 마이그레이션 상태를 먼저 확인한다. 로그인 명령의 출력에 토큰을 복사하지 않는다.

```sh
npx wrangler login
npx wrangler d1 create arcade
```

생성 결과에서 공개 리소스 식별자인 D1 `database_id`를 확인하고 소스 `wrangler.jsonc`의 `d1_databases[0].database_id`에 넣는다. 다른 계정/DB의 ID를 재사용하지 않는다. Worker 이름 `teumsae-arcade`, 바인딩 `DB`, Durable Object 바인딩 `ROOMS`/클래스 `GameRoom`, SQLite 클래스 마이그레이션을 함께 검토한다. `migrations/`의 SQL은 앱 테이블과 인덱스용이며 원격 적용 전 전체 변경을 확인한다.

```sh
npx wrangler d1 migrations list arcade --remote
npx wrangler d1 migrations apply arcade --remote
npm run deploy:check
```

D1 마이그레이션은 반드시 `--remote` 여부를 구분한다. 운영 데이터가 있는 경우 변경 전에 D1의 복구 가능 시점과 백업을 확인하고 별도 승인된 보존 경로를 사용한다. SQL 실패를 무시하고 배포를 진행하지 않는다. `0006_endless_records.sql`은 기존 행을 지우지 않고 거리/종료 사유와 무한 러너 최고 테이블을 추가한다. 새 Worker는 이 스키마가 필요하므로 SQL 적용 성공 후 배포한다. 구버전 클라이언트의 미제출 도전은 규칙 변경 안내와 함께 새 도전으로 전환하며 과거 완료 기록은 보존한다.

## 3. 실제 배포 — 승인 후에만 실행

```sh
npx wrangler deploy
```

Cloudflare Vite 플러그인이 생성한 배포 설정을 Wrangler가 사용한다. 마지막 `npm run deploy:check`를 통해 현재 소스에서 생성한 번들을 사용한다. 배포 응답의 공개 URL과 버전 ID를 안전한 운영 기록에 남긴다. Git push만으로 자동 배포하는 연결은 이 버전에 포함하지 않는다.

## 4. 공개 URL 합격 확인

브라우저 콘솔 오류·실패 요청과 아래 흐름을 함께 확인한다. 로컬 테스트의 통과 결과를 원격 결과로 옮겨 적지 않는다.

1. 이름 입력·새로고침·재방문이 같은 플레이어를 유지하는지, 동일 이름의 별도 브라우저는 다른 기록인지 확인한다. HTTPS 쿠키의 Secure·HttpOnly·SameSite=Strict 속성을 확인한다.
2. 팡팡 17×13 맵·칸 중간 정지·상자 파괴 후 3종 아이템/능력치·단계별 3~7마리 적의 비겹침·싱글 5단계, 러너 무한 진행·점프/슬라이드·실패/사용자 종료 저장·같은 시드 재도전을 확인한다. 러너 일반/일간/주간의 거리·수집 순위, 팡팡의 새 규칙 최고/랭킹 분리와 두 게임의 이전 기록 보존을 확인한다.
3. **별도 브라우저 프로필 2개 및 4개**로 각 게임 방 생성 → 코드 참가 → 전원 준비 → 동시 시작 → 실제 입력 → 결과 저장을 진행한다. 같은 프로필의 여러 탭은 독립 플레이어가 아니다.
4. 동일 시드·시작 시각·탈락·순위 일치, 5번째 참가자 거절, 탈락 후 관전을 확인한다.
5. 한 참가자의 연결을 끊고 15초 이내 재접속, 유예 초과, 자발적 퇴장, 방장 이전, 같은 맵/새 맵 재대결을 확인한다. 재접속으로 탈락이 취소되어서는 안 된다.
6. 전원 퇴장 후 빈 방 정리, 경기 종료 후 입력·타이머 정지, 중단 경기가 승패로 바뀌지 않는지 확인한다. 배포/재시작 중인 경기는 복구를 보장하지 않고 중단 처리한다.
7. 요청 제한 오류에서 재시도·로비 복귀가 가능한지, 작은 화면에서 안내·기록·로비가 겹치지 않는지 확인한다. 게임 조작 지원은 PC 키보드다.
8. 아래 Cloudflare 지표를 기록한 뒤 무료 용량 안에서 운영 가능한지 판단한다. 처음에는 지인/수업 소규모 초대방으로 제한한다.

## 무료 한도와 관찰

2026-09-09 배포 직전에 아래 공식 문서와 계정 대시보드의 현재 Free 플랜을 확인했다. 계정 내 다른 앱 사용량도 합산될 수 있다.

| 자원 | Free 기준 | 확인할 것 |
| --- | --- | --- |
| Workers | 일 100,000 요청, 호출당 CPU 10ms | Workers & Pages → Worker → Metrics의 요청·오류·CPU 시간. 정적 에셋 요청과 API 호출을 구분 |
| Durable Objects | 일 100,000 요청, 13,000 GB-s 실행량 | Durable Objects의 요청·활성 시간·오류. WebSocket 수신 메시지는 요금 계산에서 20:1로 집계되며 송신은 요청 요금 대상이 아님 |
| DO SQLite | 일 5,000,000 행 읽기, 100,000 행 쓰기, 총 5GB | 체크포인트 저장·알람도 저장소 사용량에 포함. 게임 틱마다 저장하지 않는 구조 유지 |
| D1 | 일 5,000,000 행 읽기, 100,000 행 쓰기, 총 5GB | D1 → 데이터베이스 → Metrics의 Row metrics와 저장량. API 제한 카운터도 읽기/쓰기 사용 |

출처: [Workers 요금](https://developers.cloudflare.com/workers/platform/pricing/), [Durable Objects 요금](https://developers.cloudflare.com/durable-objects/platform/pricing/), [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/).

일간 한도는 UTC 00:00(한국 09:00) 재설정이다. 무료 한도를 넘으면 요청/작업이 실패할 수 있으며 자동으로 유료 운영이 되는 것으로 가정하지 않는다. 게임 중 20Hz 타이머가 켜진 방은 활성 실행량을 소비한다. 비활성 대기방은 Hibernation을 사용하지만 활발한 메시지·게임 중에는 휴면 절감이 적용되지 않는다. 로컬 4인 검증은 원격 동시 방 수·지연·CPU 여유의 증거가 아니다.

첫 원격 측정은 게임별 4인 한 경기의 시작/종료 시각, 요청 수, CPU 최대/분포, DO 활성 시간, D1 행 읽기/쓰기 증가량과 오류를 기록한다. 반복 경기의 실측치를 바탕으로 예상 일간 이용량과 계정 잔여 한도를 비교한다. 수용량을 늘리기 전에 측정하며 요금제 변경이나 자동 모니터링 연결은 별도 승인받는다.

## 오류와 복구

- 배포 실패: 현재 서비스와 원격 데이터 상태를 먼저 확인한다. 인증 실패는 안전한 로그인 경로로 해결하며 키를 출력하지 않는다. 마이그레이션 성공과 Worker 배포 성공은 별개다.
- 앱 회귀: Cloudflare의 이전 Worker 배포 버전으로 복구하는 변경을 승인받아 수행한다. DB 스키마는 자동으로 되돌아가지 않으므로 이전 코드와 현재 스키마의 호환성을 먼저 확인한다. Git reset/force push로 운영 복구를 대신하지 않는다.
- DB 문제: 추가 SQL·복구는 별도 승인 대상이다. D1 Time Travel/백업의 실제 복구 가능 범위를 계정에서 확인하고 복구 과정에서 유실될 기록을 안내한다. 데이터 삭제로 오류를 숨기지 않는다.
- 대전 중단: 서버가 복원할 수 없는 진행은 `aborted`로 저장한다. 사용자는 결과 안내 후 새 대결을 시작한다. 확정 결과 저장은 경기/플레이어 키로 중복 반영되지 않는다.
- 무료 한도 초과: 대시보드에서 Worker·DO·D1 중 제한 원인을 구분한다. 사용자에게 재시도 시점을 알리고 공개 초대 범위를 줄이는 운영 대응을 결정한다. 무승인 유료 플랜 전환을 하지 않는다.
- 개인 기록 복구: 이름은 소유권 수단이 아니다. 쿠키 삭제·180일 세션 만료·기기 변경의 복구 기능은 첫 버전에 없다.

DO 실행량은 일 13,000 GB-s의 약 0.17%이며, 이 짧은 검증의 D1/DO 저장 사용량도 무료 한도 안이었다. DO invocation의 오류 집계는 별도로 분류해야 한다. 분류 조회의 17건은 모두 `clientDisconnected`(HTTP 16, alarm 1)였고 테스트에서 실제 브라우저/소켓을 닫았다. 이를 앱 예외나 CPU 초과와 합쳐 해석하지 않는다. 이 수치는 해당 시점의 집계이며 이후 운영에서도 분류별로 확인한다.

Worker 최대 CPU 샘플은 Free의 명목 호출당 10ms보다 높았다. Worker 오류는 0이었으나 충분한 여유가 입증된 것은 아니다. 소규모 초대방으로 시작하고 공개 이용을 늘리기 전에 요청/CPU와 DO 실행량을 다시 측정한다. 장시간·여러 동시 방의 수용량, 안정적인 경기당 비용은 이번 검증으로 확정하지 않았다. 유료 전환·자동 모니터링·CI/자동 배포는 연결하지 않았다.

재조회는 `npx wrangler d1 info arcade --json`, Worker/DO Metrics 대시보드 또는 공식 [Workers GraphQL 예제](https://developers.cloudflare.com/analytics/graphql-api/tutorials/querying-workers-metrics/)와 [DO 지표](https://developers.cloudflare.com/durable-objects/observability/metrics-and-analytics/)를 사용한다.
