# 웹 미니게임 모음: 제품과 기술 결정

기준일: 2026-09-08. 이 문서는 제품 범위와 설계의 기준이며 구현 완료 보고가 아니다. 실제 진척은 [PLAN.md](PLAN.md)에 기록한다.

## 목표와 사용 경험

사용자는 이름을 입력하고 게임을 선택해 즉시 플레이한다. 각 게임에는 스테이지를 올라가는 싱글모드와 최대 4인의 실시간 멀티모드가 있다. 짧은 한 판, 빠른 재도전, 기록 경쟁을 중심으로 구성한다. 첫 게임은 폭탄을 설치하는 격자형 액션, 두 번째는 자동으로 달리는 횡스크롤 러닝이다.

- 최초 지원은 PC 키보드와 데스크톱 브라우저다. 웹 화면은 작은 화면에도 대응하되 모바일 게임 조작 완성은 후속 범위다.
- 게임 선택 → 싱글/멀티 선택 → 조작 안내/대기실 → 플레이 → 결과 → 재도전 흐름을 완성한다.
- 한국어 UI를 사용한다. 폭발 범위, 장애물, 남은 시간, 승패가 명확히 보이는 자체 테마를 만든다.
- 기존 상용 게임 이름은 장르 참고다. 제품 이름·캐릭터·이미지·음원은 자체 제작 또는 적법한 사용 권한이 있는 것으로 구성한다.

## 첫 버전의 게임 범위

| 항목 | 폭탄 게임 | 러닝 게임 |
| --- | --- | --- |
| 싱글 | 적 처치 또는 출구 도달, 최초 5단계 | 코스 완주, 최초 5단계 |
| 진행 | 완료한 단계 저장, 실패 단계 재도전 | 완료한 단계 저장, 실패 단계 재도전 |
| 변주 | 맵 배치, 파괴 벽, 적 행동, 아이템, 위험 요소 | 구간 순서, 장애물, 갈림길, 이동 발판, 수집물 |
| 멀티 | 2~4인 같은 경기장, 마지막 생존자 승리 | 2~4인 동일 코스, 결승 도착 순서 경쟁 |
| 경기 종료 | 동시 전멸 또는 시간 초과는 무승부 | 도착자 우선, 미도착자는 진행 거리, 같은 거리면 공동 순위 |
| 초기 목표 경기 길이 | 1~3분 범위에서 조정 | 1~3분 범위에서 조정 |

세부 맵 크기, 점프 높이, 적 수, 폭발 시간 등은 플레이 가능한 작은 기본값을 선택해 코드의 설정 데이터로 관리한다. 무작위 요소의 종류를 늘리는 것보다 공정하고 재도전할 수 있는 게임 한 판을 먼저 완성한다.

- 멀티는 초대 코드로 참가한다. 방장 시작, 전원 준비, 동일한 시작 시점, 관전, 재대결, 로비 복귀를 제공한다.
- 2명부터 시작할 수 있고, 최대 4명이다. 플레이어를 봇으로 자동 충원하지 않는다.
- 싱글 성장 능력치를 멀티에 가져오지 않는다. 같은 조건에서 경쟁한다.
- 러닝 멀티는 경주에 집중한다. 플레이어끼리 밀기나 공격 아이템은 후속 범위다.
- 싱글은 일시정지할 수 있다. 멀티는 개인의 일시정지나 브라우저 비활성화로 경기 시간이 멈추지 않는다.
- 짧은 접속 종료에는 제한된 재접속 유예를 제공한다. 유예 만료, 자발적 퇴장, 방장 이탈의 처리 기준을 코드와 UI에 명시한다. 재접속으로 탈락을 취소하지 않는다.

## 다양성, 난이도, 공정성

- 검증된 맵 템플릿 또는 코스 구간을 시드에 따라 조합한다. 완전 무작위 배치를 기본으로 삼지 않는다.
- 맵에 `seed`, 생성기 버전, 규칙 버전, 난이도를 연결해 같은 조건을 재현한다.
- 일반 싱글은 새 도전마다 변주하되 실패 직후 재도전은 같은 배치를 사용한다. 최근 조합 반복을 줄인다.
- 단계별 난이도 범위 안에서 요소를 섞는다. 신규 기믹은 쉬운 형태로 먼저 등장시킨다.
- 폭탄 맵은 시작 지점 탈출 공간·이동 경로·출구 접근을 검사한다. 멀티 시작점은 대칭 또는 검증된 균형 배치를 사용한다.
- 러닝 구간은 실제 이동·점프 규칙에서 통과 가능한 연결과 착지 공간을 가져야 한다.
- 생성 시도에는 상한을 두고 실패하면 검증된 기본 맵/코스로 복귀한다. 무한 생성 재시도를 만들지 않는다.
- 같은 멀티 경기의 참가자는 동일한 맵·코스·규칙·시드로 플레이한다. 재대결에서 같은 맵/새 맵을 선택한다.
- 자동 조합은 새 기믹의 무한 생성을 뜻하지 않는다. 콘텐츠 추가는 이후 개발에서 수행한다.

## 플레이어와 기록

- 회원가입·로그인 화면과 외부 인증 제품은 사용하지 않는다. 이름을 입력하면 플레이어가 만들어진다.
- 서버가 임의의 플레이어 ID와 추측하기 어려운 재방문용 세션을 발급한다. 이름은 표시값이며 중복 가능하다.
- 공개 ID와 비밀 세션을 분리한다. 세션은 적절한 쿠키 속성으로 보관하고 같은 브라우저에서 진행도를 이어간다.
- 이름만으로 기존 플레이어에 접속하거나 다른 사람 기록을 수정할 수 없어야 한다.
- 사이트 데이터 삭제·다른 기기에서 기록을 복구하는 기능은 첫 버전에 없다. 이 한계를 사용자에게 짧게 안내한다.
- 일반 싱글은 스테이지 진행도와 개인 최고 기록을 저장한다.
- 랭킹은 게임·모드·규칙 버전·기간·도전 조건을 구분한다. 다른 코스 점수를 직접 섞지 않는다.
- 일간/주간 기록 도전은 각각 해당 기간의 공통 시드와 같은 설정을 사용한다. 서로 다른 기간의 기록은 분리한다. 기간 경계는 서버가 한국 시간 기준으로 결정한다.
- 각 랭킹은 상위 기록과 내 순위 주변을 보여준다. 점수 또는 완주 시간 등 정렬 기준과 동점 규칙을 사용자에게 표시한다.
- 초대방 멀티는 친선전으로 승패·경기 결과를 저장한다. 정식 실력 등급전은 공개 매칭을 도입하는 후속 버전에 둔다. 각 게임의 첫 랭킹은 싱글 기록 도전으로 충족한다.

## 확정 기술 스택

| 역할 | 선택 |
| --- | --- |
| 언어 | TypeScript |
| 웹 화면 | React + Vite |
| 게임 렌더링·입력·사운드 | Phaser |
| 스타일 | 일반 CSS |
| 정적 파일·HTTP API | Cloudflare Workers + Static Assets |
| 실시간 게임방 | SQLite 저장소를 사용하는 Durable Objects + WebSocket |
| 영구 기록 | Cloudflare D1 |
| 데이터 접근 | 매개변수를 바인딩한 직접 SQL |
| 패키지 관리 | npm, 단일 package.json과 package-lock.json |
| 품질 도구 | TypeScript 검사, Biome, Vitest, Playwright |

최초 설치 허용 후보는 `react`, `react-dom`, `phaser`, `typescript`, `vite`, `@vitejs/plugin-react`, `@cloudflare/vite-plugin`, `wrangler`, `@types/react`, `@types/react-dom`, `@types/node`, `@cloudflare/workers-types`, `@biomejs/biome`, `vitest`, `@playwright/test`와 그 정상적인 전이 의존성이다. 실제 구성에 필요한 것만 설치한다. Workers 타입을 생성해 사용하는 경우 중복 타입 패키지는 설치하지 않는다. Playwright 검증에 필요한 브라우저 설치도 실행 프롬프트 범위에 포함한다.

초기에는 Express, Colyseus, Supabase, Drizzle, Better Auth, 별도 상태관리·UI 라이브러리, 모노레포 빌드 도구를 도입하지 않는다. 이는 이전 제안에서 무료 배포와 가벼운 운영을 우선하며 변경한 결정이다.

## 구조와 책임

아래는 구현 시 기본 구조다. 파일은 실제 기능을 구현할 때 만든다.

```text
src/
  web/                  React 화면과 공통 CSS
  games/
    bomber/             폭탄 게임의 Phaser 화면
    runner/             러닝 게임의 Phaser 화면
  core/
    bomber/             화면 없이 실행되는 폭탄 게임 규칙·맵 생성
    runner/             화면 없이 실행되는 러닝 게임 규칙·코스 생성
  shared/               필요한 통신 타입과 공통 값
  server/
    index.ts            Workers HTTP 진입점
    rooms/              게임별 Durable Object 방
    db/                 매개변수 SQL과 저장 함수
migrations/             검토 가능한 D1 SQL
public/                 배포할 자체 게임 에셋
tests/e2e/              사용자 흐름 검증
```

- 웹 빌드에 서버 코드·세션 비밀값이 포함되지 않도록 경계를 유지한다.
- 싱글은 브라우저에서 계산한다. 서버는 발급한 도전 정보, 플레이 시간, 가능한 점수, 단계 순서, 제출 중복을 확인한다.
- 이 싱글 검증은 정교한 클라이언트 조작이나 봇을 완전히 차단하지 못한다. 초기 랭킹은 보상이 걸리지 않은 가벼운 기록 경쟁으로 운영한다. 재실행 검증·고급 부정행위 탐지는 후속 범위다.
- 멀티는 방 하나당 Durable Object 하나가 진행 상태와 판정을 소유한다. 참가자는 입력을 전달하며 클라이언트는 보간/예측으로 화면을 부드럽게 표시한다.
- 렌더링·통신·시뮬레이션 주기를 분리한다. 동일 코어를 쓰더라도 싱글과 멀티의 모드 규칙은 명시적으로 구분한다.
- D1에는 진행도·개인 기록·도전 기록·확정 경기 결과를 저장한다. 경기 ID 등으로 재시도와 중복 반영을 방지한다.
- 방의 일시 상태와 플랫폼의 영구 기록은 분리한다. 서버 재시작으로 복구할 수 없는 경기는 중단으로 표시하고 임의의 승패를 기록하지 않는다.

## 무료 배포와 운영 경계

- Cloudflare Free에서 시작한다. 웹과 Worker를 같은 프로젝트·출처로 배포하는 구성을 우선한다.
- 실제 배포 전 Wrangler 설정, 로컬 D1 SQL 적용, 빌드, 배포 번들 검증, README의 배포 안내를 준비한다.
- 대전 중 계속 실행하는 타이머는 무료 실행량을 소비한다. 휴면은 비활성 대기방에 활용하고 경기 중에도 무조건 무료라고 가정하지 않는다.
- 빈 방을 정리하고 경기 시간·메시지 크기·입력 빈도·API 제출 빈도에 상한을 둔다. 표시용 랭킹 조회는 필요한 범위만 읽는다.
- 개발 기본값은 짧은 경기이며 무료 한도 내 실제 수용량은 요청량·방 실행 시간·D1 사용량으로 측정한다. 방당 4명이라는 조건만으로 전체 이용량이 무료라고 단정하지 않는다.
- 요청 제한 또는 서버 종료 시 오류를 설명하고 재시도·로비 복귀가 가능해야 한다.
- 실제 리소스 생성·배포·원격 SQL 적용은 AGENTS의 승인 경계를 따른다. 로컬 확인을 실제 Cloudflare 배포 성공으로 표시하지 않는다.

## 후속 범위

모바일 게임 조작, 공개 자동 매칭·멀티 등급전, 봇, 계정 복구·기기 동기화, 상점·재화·채팅·길드, 유료 서비스, 정교한 싱글 리플레이 검증, 세 번째 이후 게임은 첫 Goal 범위 밖이다. 필요 시 별도 목표와 완료 조건을 정한다.

## 근거와 재확인

아래는 2026-09-08 설계 시 확인한 공식 문서다. 설치 버전·요금·플랫폼 한도는 구현·배포 시점에 다시 확인한다.

- [Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/): 정적 웹과 서버 코드를 함께 배포.
- [Durable Objects 한도](https://developers.cloudflare.com/durable-objects/platform/limits/): Free에서 SQLite 저장소 지원.
- [Durable Objects 요금](https://developers.cloudflare.com/durable-objects/platform/pricing/): 무료 요청·실행량 한도와 초과 시 실패.
- [Durable Object 수명 주기](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/): 타이머와 휴면 조건.
- [D1](https://developers.cloudflare.com/d1/), [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/): SQLite 의미 체계를 갖는 관리형 DB.
- [Phaser 프로젝트 템플릿](https://docs.phaser.io/phaser/getting-started/project-templates): React·Vite·TypeScript 연동.

## 구현 결정

- P1: 제품 표시는 ‘틈새 오락실’, 게임은 ‘팡팡 아레나’와 ‘바람 러너’. 아이보리·주황·청록, 한국어 중심 UI를 사용한다. `public/arcade.svg`는 직접 작성한 원본 그림이며 외부 상용 에셋을 사용하지 않았다.
- Phaser는 공식 버전 문서와 일치하는 안정 3.90.0을 최초 선택했다. 나머지 최초 버전은 package-lock.json을 기준으로 한다.
- 세션은 256비트 난수, DB에는 SHA-256 해시만 저장. HttpOnly·SameSite=Strict, HTTPS에서는 Secure. 유효기간 180일이며 만료·브라우저 데이터 삭제 시 복구하지 않는다.
- 검증 환경에 Browser 플러그인 스킬이 없으므로 Playwright Chromium을 사용한다. 단계별 기능 검증을 우선하고 별도 디자인 승인·반복 리뷰는 추가하지 않는다.

- 폭탄 규칙: 11×9 격자, 50ms 고정 틱, 150ms 이동 간격, 폭탄 1.8초·기본 2칸·최대 동시 2개, 불꽃 0.5초, 제한 90초. 단일 틱의 연쇄 폭발은 폭발 직전 벽 배치를 공유한다. 출구 위 상자를 부수고 도착하면 완료한다.
- 폭탄 난이도: 1~5단계에서 파괴벽 밀도와 적 순찰 속도가 증가한다. 2단계부터 폭발 범위 아이템, 4단계부터 주기적 위험 타일. 시작 회랑과 출구 접근을 보장하며 생성은 최대 6회, 실패하면 검증된 기본 배치로 복귀한다.
- 일반 싱글 기록: 서버가 도전 ID·시드·단계를 발급하고 본인 세션·단계 순서·시간·점수 범위·중복 제출을 확인한다. 일시정지 가능 시간을 포함해 도전은 발급 후 2시간 유효하다. 실패 직후 같은 맵 재도전은 기존 도전의 소유권을 검사한 뒤 시드를 재사용한다.

- 실시간 방: 8자리 초대 코드, 2초 공통 카운트다운, 20Hz 서버 시뮬레이션·10Hz 상태 전송, 클라이언트는 입력을 최대 20Hz 전송하고 렌더링에서 위치를 보간한다. 메시지는 최대 512바이트·초당 40회이며 순번이 지난 입력과 클라이언트 승패/위치 주장은 반영하지 않는다.
- 방 수명: 15초 재접속 유예 후 탈락, 자발적 퇴장 즉시 탈락, 방장 권한은 연결된 잔여 참가자부터 이전. 종료 후 같은/새 맵을 선택하고 전원이 다시 준비한다. 대기방은 15분 만료, 빈 방은 알람으로 정리한다. 대기 중에는 게임 interval 없이 WebSocket Hibernation을 사용한다.
- 서버 실행이 끊겨 진행을 복구하지 못하면 중단 결과만 저장하며 승패를 만들어내지 않는다. 종료 결과는 D1 batch와 복합 PK로 재시도해도 한 번만 반영하고 저장 전에는 재대결을 막는다.

- 기록 도전은 누구나 고정 3단계에 도전할 수 있다. 한국 시간 일간(자정)·주간(월요일 자정) 시작 날짜와 게임·모드·규칙 버전으로 공통 시드를 계산한다. 발급받은 기간의 기록으로 저장하며 기간이 바뀐 뒤 재도전은 새 도전을 발급한다.
- 랭킹은 플레이어당 조건별 최고 한 건. 폭탄은 점수 내림차순 후 시간 오름차순, 러닝은 시간 오름차순 후 점수 내림차순. 두 값이 같으면 공동 순위이고 다음 순위는 건너뛴다. 상위 10명과 내 순위 주변 최대 7명, 내 기록을 별도로 반환한다. 표시 순서의 마지막 기준은 공개 ID이며 순위 계산에는 포함하지 않는다.
- 일반 싱글 개인 최고는 개인 진행 참고용이며 공통 시드 랭킹과 합산하지 않는다. 최근 플레이는 본인의 완료/실패·친선 대전 최대 20건을 표시한다.

- 러닝 규칙: 50ms 고정 틱, 기본 이동은 단계별 틱당 6.5~8.5px, 점프 초기 속도 12·중력 0.8, 수집물은 40틱 동안 +1.2px 속도. 7,200~9,600px 코스를 약 1분에 완주하며 제한은 90초다.
- 러닝 난이도: 1단계 장애물, 2단계 틈, 3단계 갈림길(↑↓로 윗길/아랫길 선택), 4단계 이동 발판, 5단계 더 높은 장애물과 넓은 틈. 구간 간 300px 이상 착지 여유를 검사하고 기본/가속 상태 점프 궤적 모두 통과해야 채택한다.
- 러닝 멀티는 공통 3단계 코스를 사용하며 완주 틱 오름차순, 미완주는 진행 거리 내림차순이다. 동점은 공동 순위다. 플레이어 간 밀기·공격은 없다. 방·기록 저장은 공유하지만 러닝의 물리·판정은 별도 순수 TypeScript 코어가 맡는다.

- P6 API 제한: 세션 생성은 접속 IP의 SHA-256 해시별 60회/분, 게임·방 POST는 서버가 확인한 플레이어별 합계 40회/분이다. D1의 조건부 UPSERT로 동시 요청도 상한을 넘지 않게 하며 429/Retry-After를 반환한다. 한 시간 이상 지난 카운터는 요청 시 최대 100개씩 정리한다. 공유 IP의 수업에서는 세션 생성 제한을 함께 사용하므로 한꺼번에 60명을 넘겨 입장하지 않는다.
- 저장 응답이 유실되면 같은 도전 재제출의 409를 소유자 전용 최근 기록과 대조해 완료를 확인한다. 확인 전에는 새 재도전으로 미저장 결과를 덮지 않는다. 서버 오류·방 만료로 퇴장 API가 실패해도 로비로 나가며 소켓 종료/유예로 서버 참가 상태를 정리한다.
- 외부 폰트 요청을 제거하고 시스템 한국어 글꼴을 사용한다. 첫 버전은 자체 SVG·Phaser 시각 효과를 사용하며 음원은 포함하지 않는다.
