# 개발 계획과 진행 기록

제품 기준: [PROJECT.md](PROJECT.md). 작업·Git 규칙: [../AGENTS.md](../AGENTS.md). 실행 범위: [START.md](START.md).

## 진행 원칙

P1부터 P6까지 순서대로 진행한다. 각 단계 안에서는 독립적인 기능·수정이 검증될 때마다 커밋·push한다. 한 단계 전체를 거대한 커밋으로 묶을 필요는 없다. 기본은 단일 에이전트 실행이며 기능별 별도 리뷰 에이전트는 요구하지 않는다.

아래 항목은 합격 조건이다. 체크되지 않은 기능을 구현된 것으로 간주하지 않는다. 단계별 상세 작업 목록은 해당 단계에 들어갈 때만 필요한 만큼 만든다.

## 현재 상태

- P1 완료: 로컬 실행, 이름 입력, 세션 분리와 재방문을 검증했다.
- GitHub 대상은 `WooRung/lgd-minigame-proj`, 브랜치는 `main`이다. 커밋·push 최신 상태는 실제 Git에서 확인한다.
- P2 완료: 폭탄 싱글 5단계와 저장·이어하기. P3 실시간 대전까지 완료했으며 P4 기록 경쟁까지 완료했고 다음은 P5 러닝 게임이다.

## P1. 로컬 개발 기반과 이름 입력 흐름

- [x] 승인된 최소 스택의 단일 패키지와 lockfile, 개발·빌드·검사 스크립트가 있다.
- [x] Workers·D1·Durable Objects를 로컬에서 실행할 설정과 로컬 전용 초기 SQL이 있다.
- [x] 이름 입력 → 플레이어 세션 → 게임 선택이 실제 API와 연결된다.
- [x] 같은 이름의 다른 플레이어가 기존 진행도를 소유하지 않으며, 같은 브라우저 재방문은 같은 플레이어로 인식된다.
- [x] 오류·로딩·빈 랭킹·게임 준비 상태가 명확하고 아직 없는 게임을 플레이 가능한 것처럼 표시하지 않는다.
- [x] README에 다른 개발자가 재현할 수 있는 로컬 실행 방법과 실제 사용 명령을 기록했다.

검증: 타입·형식·빌드, 세션 경계 테스트, 이름 입력/재방문 브라우저 흐름. 이 단계가 첫 독립 실행 가능한 체크포인트다.

## P2. 폭탄 게임 싱글과 맵 다양성

- [x] 이동, 폭탄 설치, 폭발 범위, 연쇄 폭발, 파괴 벽, 적 또는 출구 목표가 실제로 동작한다.
- [x] 5단계의 진행·실패·일시정지·같은 배치 재도전·결과 화면·다음 단계가 연결된다.
- [x] 시드 기반 생성, 난이도 범위, 안전한 시작점, 이동 가능성 검사, 기본 맵 복귀를 구현했다.
- [x] 스테이지 완료 기록이 실제 저장되고 재방문해 이어할 수 있다.
- [x] 읽기 쉬운 자체 그래픽과 효과가 있고 입력·판정·피드백이 일치한다.

검증: 폭발·연쇄·충돌·생성의 핵심 테스트, 고정 시드 묶음의 유효성, 실제 브라우저에서 실패/완료/재도전/이어하기.

## P3. 폭탄 게임 최대 4인 실시간 대전

- [x] 초대방 생성·참가·준비·시작이 가능하고 2인과 4인으로 경기한다. 5번째 참가자는 거절한다.
- [x] 방이 공통 시드·시작 시점·진행 상태를 소유하고 이동·폭발·승패를 판정한다.
- [x] 참가자 화면에 같은 폭발·탈락·경기 결과가 반영된다.
- [x] 재접속 유예·퇴장·방장 이탈·시간 초과·무승부·탈락 후 관전을 처리한다.
- [x] 같은 맵/새 맵 재대결과 로비 복귀가 가능하고 이전 경기 타이머·상태가 섞이지 않는다.
- [x] 입력·메시지 크기·빈도와 세션/방 권한을 검증하며 결과는 중복 반영되지 않는다.

검증: 방/입력/결과 경계 테스트, 독립 브라우저 세션 2개와 4개의 실제 경기, 접속 종료·재접속·초과 인원·재대결.

## P4. 폭탄 게임 기록 경쟁과 공통 랭킹

- [x] 일반 싱글 개인 기록과 일간/주간 공통 조건 도전을 제공한다.
- [x] 게임·모드·규칙 버전·기간·시드별 기록이 분리되고 정렬·동점 기준이 명확하다.
- [x] 상위 기록, 개인 최고, 내 순위 주변, 기록이 없는 상태를 보여준다.
- [x] 서버가 도전 발급·시간·가능한 점수·진행 순서·중복 제출을 검사한다.
- [x] 친선 멀티 결과를 저장하며 이를 실력 등급전으로 표시하지 않는다.
- [x] 사이트 데이터 삭제/기기 변경의 기록 복구 한계와 싱글 기록 검증 범위를 문서화했다.

검증: 기간 경계·정렬·동점·중복·잘못된 제출 테스트, 실제 게임 결과의 저장/조회 흐름. 세션/소유권 검증은 변경 범위에 맞춰 확인한다.

## P5. 러닝 게임 싱글·멀티·랭킹

- [ ] 자동 달리기, 점프 등 최소 조작, 충돌, 수집, 결승점과 5단계 진행을 구현했다.
- [ ] 시드 기반 코스 변주와 구간 연결/착지 가능성 검사, 기본 코스 복귀가 있다.
- [ ] 2~4인이 같은 코스·시작 시점·규칙으로 경주하며 서버가 순위와 제한 시간 종료를 판정한다.
- [ ] 실패/탈락·관전·재접속·재대결·기록 저장과 게임별 일간/주간 랭킹을 연결했다.
- [ ] 폭탄 게임의 구현을 거대한 범용 엔진으로 재작성하지 않고 실제 공통 방/기록 처리만 재사용했다.

검증: 이동·점프·충돌·구간 연결·순위 테스트, 싱글 스테이지 진행, 독립된 2인·4인 브라우저 경주, 각 게임 기록 분리 확인.

## P6. 첫 버전 통합과 Cloudflare 배포 준비

- [ ] 두 게임의 선택 → 싱글/멀티 → 종료 → 재도전이 실제로 동작하고 주요 오류를 처리한다.
- [ ] 화면 이탈/경기 종료 후 타이머·리스너·WebSocket을 정리하며 빈 방에 게임 루프가 남지 않는다.
- [ ] 필요한 표적 테스트·타입·형식·빌드·브라우저 검증이 통과하고 알려진 치명적 문제는 없다.
- [ ] Wrangler 배포 번들을 로컬에서 검증했다. 원격 작업 없이 검증 가능한 범위를 명확히 기록했다.
- [ ] README에 최초 Cloudflare 리소스 준비, SQL 적용, 배포, 설정값 위치, 확인/복구 절차와 무료 한도를 설명했다.
- [ ] 무료 실행량/DB 사용량을 확인할 방법과 최초 4인 원격 검증 항목을 정리했다. 로컬 성능으로 원격 용량을 단정하지 않는다.
- [ ] P1~P6의 필수 변경과 문서가 한국어 커밋으로 GitHub에 반영되었다.
- [ ] 아래 증거 기록과 후속 원격 작업 목록이 최신이다.

이 단계까지가 시작 Goal의 종료 범위다. 실제 공개 배포를 완료했다고 보고하지 않는다.

## D1. 실제 Cloudflare 배포 — 별도 승인 후

- [ ] 사용자가 계정·대상 리소스·무료 플랜과 실제 배포 범위를 승인했다.
- [ ] 필요한 원격 D1/방 바인딩/설정을 준비하고 검토한 SQL을 적용했다.
- [ ] 공개 URL에서 이름 입력·진행도·두 게임·2~4인 경기·랭킹이 동작한다.
- [ ] 실제 요청량·방 실행량·D1 사용량과 접속 종료 처리, 복구 방법을 확인했다.

CI/자동 배포 연결은 이 단계에서도 별도 명시적 요청이 있을 때 설정한다.
