## 진행 원칙

이번 개선은 E1 문서 → E2 러너 → E3 팡팡 → E4 통합 순서로 진행한다. P1~P6은 이전 버전의 완료 이력으로 보존한다. 각 단계 안에서는 독립적인 기능·수정이 검증될 때마다 커밋·push한다. 한 단계 전체를 거대한 커밋으로 묶을 필요는 없다. 기본은 단일 에이전트 실행이며 기능별 별도 리뷰 에이전트는 요구하지 않는다.

아래 항목은 합격 조건이다. 체크되지 않은 기능을 구현된 것으로 간주하지 않는다. 단계별 상세 작업 목록은 해당 단계에 들어갈 때만 필요한 만큼 만든다.

## D1. 실제 Cloudflare 배포 — 2026-09-09 승인 후 실행

- [x] 사용자의 실제 배포 요청과 브라우저 로그인 승인을 받고, 단일 계정의 Workers 현재 Free 플랜·동명 Worker 없음·D1 목록 비어 있음을 확인했다.
- [x] APAC에 `arcade`를 새로 생성하고 검토한 `0001`~`0006` SQL을 모두 적용했다. 실제 계정/D1 ID와 SQLite GameRoom 바인딩으로 Worker를 배포했다.
- [x] 공개 HTTPS에서 이름 입력·재방문·동명이인 분리·보안 쿠키, 팡팡 5단계/아이템/진행도, 러너 3테마/점프/슬라이드/종료 저장/일반 랭킹, 게임별 독립 2인·4인 대전/재접속/재대결을 검증했다.
- [x] Worker 요청/오류/CPU와 D1 사용량을 원격 조회하고 배포 버전·리소스·복구 절차를 DEPLOY에 기록했다.
- [x] 집계 지연 후 DO 활성 시간·실행량·CPU·SQLite 사용량을 확인했다. 짧은 검증에서는 Free 실행량/저장 한도 안이며, 장시간·여러 동시 방의 수용량은 미검증이다. Worker CPU 최대 샘플과 접속 종료 집계의 한계는 DEPLOY에 기록했다.

공개 주소: [틈새 오락실](https://teumsae-arcade.ys-475.workers.dev). 배포 버전 `1bd20c3d-1ca0-4b1d-ae2b-162baf7f8734`, 초기화 CPU 4ms. `npm run deploy:check`와 실제 `npx wrangler deploy` 성공, 정적 파일 7개 업로드/에셋 9개, Worker 58.09KiB(gzip 16.99KiB), DB/ROOMS 바인딩 확인.

공개 검증 1차: `ARCADE_REMOTE_VERIFY=1 npx playwright test --config playwright.remote.config.ts` 당시 대상 8개가 6.1분에 모두 통과했다. 팡팡 2인 24.5초/4인 36.6초, 러너 2인 56.5초/4인 약 1분. 동일 시작/시드·상태/결과 일치, 팡팡 5번째 참가자 거절·탈락 후 관전/재접속·방장 이전, 실제 원격 기록 저장을 확인했다. 합성 점수·부하 fixture는 원격에서 실행하지 않았다.

배포 중 발견한 수정: Records가 도전 종료 후 기간을 기본값으로 초기화했다. App의 현재 RunMode를 Records에 전달해 선택 기간을 유지한다. `deployment-flows.spec.ts --grep '두 게임 일간'` 로컬 1개/60초 통과: 팡팡·러너 각각 일간/주간 실제 플레이와 저장, 복귀 시 게임·기간·내 순위 확인. 수정 커밋 `2ebc953`을 origin/main에 반영한 뒤 재배포했다. 현재 버전은 `d2b5fe9d-0d47-4ff6-a647-8dcfe376efac`(초기화 5ms)이며 같은 기간 복귀 흐름의 공개 재검증 1개/약 1.2분이 통과했다. 새 검증 작성 중 잘못 가정한 label/준비 속성은 실제 화면에 맞게 수정했다.

실제 D1 ID 반영 후 로컬 개발이 빈 별도 DB를 바라보는 것도 확인했다. 기존 SQLite의 플레이어 160명 보존을 읽기 전용으로 확인하고 `preview_database_id`를 기존 로컬 식별자로 고정했다. `wrangler d1 execute arcade --local --config wrangler.jsonc`에서 기존 160명 조회 후 위 로컬 브라우저 흐름이 통과했다. 원격 DB로 로컬 기록을 복사하거나 기존 로컬 파일을 삭제하지 않았다.

공개 검증 최종: 기본 8개에 기간별 랭킹 1개와 유예/정리 1개를 더한 10개 항목이 통과했다. 유예 검증은 26.8초에 통과: 15초 초과 후 탈락, 종료 틱 정지, 재입장 거절, 전원 퇴장 후 방 404. 수정 후에는 변경된 기간 복귀 흐름만 재검증했으며 게임 코어/통신이 바뀌지 않은 기존 8개는 반복하지 않았다. 타입·Biome·재빌드/dry-run 통과, 배포 API에서 실제 원격 D1 ID와 DO 네임스페이스를 확인했다. D1/DO 초기 사용량은 Free 한도 안이고 Worker 오류/DO CPU·메모리 초과는 0이었다. 최대 Worker CPU 14.004ms 샘플과 전체 공개 규모/장시간 수용량은 DEPLOY의 운영 한계로 남긴다.

CI/자동 배포 연결·요금제 변경은 수행하지 않았다. 후속 설정은 별도 명시적 요청이 있을 때 수행한다.
