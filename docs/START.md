# Goal 실행 계약

이 파일은 사용자가 실행할 프롬프트의 상세 지시다. 파일을 읽거나 수정하는 요청만으로 구현을 시작하지 않는다. 아래 명령을 사용자가 제출하면 이 계약의 구현 작업을 수행한다.

## 실행할 명령

Codex의 이 프로젝트 채팅 입력창에 아래 한 줄을 붙여 넣는다. 셸의 `goal` 명령이나 `codex goal` 하위 명령이 아니다.

```text
/goal AGENTS.md, docs/PROJECT.md, docs/PLAN.md, docs/START.md를 읽고 실행 계약에 따라 P1~P6을 순서대로 완성해 줘. 이름만 입력해 시작하는 웹 미니게임 모음에서 폭탄 게임과 러닝 게임 각각의 싱글 5단계, 최대 4인 실시간 대전, 게임별 기록·랭킹을 실제로 동작시키고 Cloudflare 무료 배포 준비까지 마쳐 줘. 이 범위의 최초 최소 의존성 설치, 프로젝트 내부 로컬 설정, 로컬 전용 D1 초기화와 테스트를 승인하며, 검증된 기능·수정마다 한국어로 커밋하고 origin/main에 push해 줘. 승인된 일반 작업은 단계마다 재확인하지 말고 계속 진행하되, 실제 배포·원격 DB 변경·계정/결제·시크릿·CI/자동 배포 설정은 실행 전 별도 승인을 받아 줘. 필수 검증과 GitHub 반영을 완료 조건으로 삼고, 남은 원격 작업은 명확히 인계해 줘.
```

## 목표

PROJECT의 첫 버전 전체를 구현하고 PLAN의 P1~P6 합격 조건을 충족한다. 게임 화면만 보여주는 시연물이 아니라 이름 입력·플레이·진행도·실시간 대전·기록 조회가 연결된 결과를 만든다. 실제 배포는 준비 상태로 인계하며 원격 운영 작업을 묵시적으로 실행하지 않는다.

## 시작 순서

1. 프로젝트 문서, 현재 Git 브랜치·원격·작업 트리, 기존 코드·패키지·PLAN 상태를 확인한다.
2. 활성 Goal이 있으면 동일 목표인지 확인해 이어간다. 이미 Goal 명령으로 등록되었다면 중복 생성하지 않는다. Goal 기능을 쓸 수 없는 환경이면 그 사실을 알리고 완료 여부를 꾸며내지 않는다.
3. 현재 상태에서 첫 미완료 단계를 선택한다. 완료한 체크포인트를 처음부터 재구현하지 않는다.
4. 이번 체크포인트의 변경과 검증 범위를 짧게 알리고 구현한다. 최초에는 로컬 실행과 이름 입력 흐름까지 이어지는 P1을 완성한다.

## 실행 범위와 품질

- 제품·스택·코드·Git 규칙은 연결된 문서를 따른다. 이 명령은 해당 범위의 구현을 승인한다.
- PROJECT의 최초 최소 의존성 설치와 호환 버전 선택, 로컬 설정 파일, 로컬 테스트용 D1 SQL 적용을 허용한다. 실제 서비스용 비밀값 주입과 원격 운영 리소스 변경은 별도 승인을 따른다.
- 세부 게임 수치·표현은 단순하고 플레이 가능한 기본값을 선택한다. 선택한 주요 규칙은 코드 설정과 제품 문서에 반영한다.
- 매 체크포인트에서 해당 기능의 합격 조건에 필요한 검증을 한 번 통과시킨다. 실패하면 원인을 수정하고 영향 범위를 다시 검증한다.
- 기본은 단일 에이전트의 순차 진행이다. 별도 요청이 없는 다중 에이전트 검토 체계나 무제한 리뷰 루프를 도입하지 않는다.
- 독립적인 기능·수정마다 PLAN을 갱신하고 한국어 커밋·push한다. 새 단계에 들어갔다는 이유만으로 빈 커밋을 만들지 않는다.
- 장애가 생기면 승인된 안전한 대안을 시도한다. 사용자의 정보·접근·승인이 꼭 필요한 경우 필요한 항목과 이유를 한 번에 구체적으로 요청하고 독립적으로 가능한 작업을 계속한다.
- 실행 환경의 승인/보안 제약을 우회하지 않는다. Goal 실행을 배포·결제·원격 데이터 변경의 포괄적 승인으로 간주하지 않는다.

## 완료 조건과 보고

P1~P6의 필수 기능이 구현되고 필요한 로컬·브라우저·배포 번들 검증을 통과했으며 승인된 저장소로 커밋이 반영되었을 때 Goal을 완료한다. 외부 차단으로 GitHub 반영이나 필수 검증이 끝나지 않았다면 그 상태를 완료로 표시하지 않는다.

최종 보고에는 실행 방법, 완료한 게임/모드, 핵심 검증 결과, 마지막 커밋과 push 상태, 실제 배포 전에 사용자가 해야 할 승인/설정만 간결하게 정리한다. 실제 공개 배포 성공과 배포 준비 완료를 구분한다.

## 명령 사용 근거

2026-09-08 공식 문서에서 `/goal <objective>` 형식과 파일을 참조하는 목표를 확인했다. 목표 문자열에는 길이 제한이 있으므로 상세 지시는 이 파일에 둔다.

- [Goal 명령](https://learn.chatgpt.com/docs/developer-commands?surface=cli): 목표 설정·조회·일시정지·재개.
- [Goal 실행 가이드](https://learn.chatgpt.com/use-cases/follow-goals): 검증 가능한 종료 조건과 체크포인트.
- [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md): 프로젝트 지침 로딩.

현재 앱/CLI에 `/goal`이 보이지 않으면 지원 여부와 기능 설정을 먼저 확인한다. 전역 설정 변경은 사용자 요청 없이 수행하지 않는다. Goal은 모델 사용량·실행 환경·권한 제약을 없애는 기능이 아니다.
