# Goal 실행 계약 — 게임 개선

이 계약은 사용자가 이번 개선 Goal을 실행할 때 적용한다. 문서를 읽거나 프롬프트를 작성해 달라는 요청만으로 Goal을 생성하지 않는다. 기존 P1~P6 완료 이력은 PLAN에 보존하고 다시 구현하지 않는다.

## 복사해서 실행할 프롬프트

```text
/goal AGENTS.md, docs/PROJECT.md, docs/GAMEPLAY.md, docs/PLAN.md, docs/START.md와 실제 코드·Git 상태를 확인하고 이번 개선 계약의 E1~E4를 완성해 줘. 활성 Goal이 있으면 중복 생성하지 말고 이어가 줘. 문서 보완 → 무한 바람 러너 → 넓은 팡팡 아레나 → 통합 검증 순서로 단일 에이전트가 진행해 줘. 러너는 빠른 자동 달리기·점프·슬라이드·3테마/12패턴·끝없는 구간 생성과 정리·거리/수집 랭킹을, 팡팡은 넓은 맵·칸 내부 연속 이동·상자 파괴 후 3종 아이템·겹치지 않는 다수 적을 실제로 구현해 줘. 두 게임의 사람 2~4인 서버 권위 대전·재접속·관전·재대결을 유지하고 이전 진행도/기록은 삭제하지 말고 새 규칙과 분리해 줘. 프로젝트 내부 코드·문서·로컬 설정과 필요한 로컬 D1 마이그레이션·테스트를 승인한다. 검증된 독립 기능·수정마다 한국어로 커밋하고 승인된 origin/main에 push해 줘. 추가 의존성·실제 배포·원격 DB·계정/결제·시크릿·CI/자동 배포는 별도 승인받아 줘. 필수 기능·실제 브라우저 검증·배포 번들 검증·GitHub 반영이 모두 끝났을 때만 완료하고 남은 원격 작업과 한계를 인계해 줘.
```

## 목표와 문서 역할

- PROJECT: 제품 범위·스택·데이터 보존·운영 경계.
- GAMEPLAY: 조작·생성·난이도·충돌·아이템·점수·종료의 구현 규칙. 이번 Goal 요구사항을 생략하거나 선택 기능으로 낮추지 않는다.
- PLAN: E1~E4 합격 조건·실제 검증 증거·다음 작업. P1~P6 체크는 과거 버전 이력이며 새 기능의 완료 증거가 아니다.
- README/DEPLOY: 검증된 현재 실행 방법과 별도 승인할 원격 작업 인계.

## 순서와 승인

1. 문서와 실제 Git 브랜치·원격·작업 트리·패키지·코드를 확인한다. 활성 Goal은 이어가고 중복 생성이나 임의 예산 설정을 하지 않는다.
2. E1 문서 정합성을 먼저 보완한다. 그 후 재확인 없이 E2 러너, E3 팡팡, E4 통합을 순차 구현한다. 사용자 변경을 보존한다.
3. 독립 기능이 연결된 최소 단위마다 필요한 검증을 통과시키고 PLAN에 증거를 기록한 뒤 한국어 커밋·push한다. 미연결 화면·가짜 랭킹·통신 코드만으로 기능 완료를 표시하지 않는다.
4. 프로젝트 내부 코드/문서/로컬 설정, 필요한 로컬 전용 D1 SQL 적용과 테스트는 승인되었다. 기존 패키지와 스택을 유지한다. 추가·업그레이드·제거 의존성, 브랜치/히스토리 변경, 실제 배포·원격 DB·계정·결제·시크릿·CI/자동 배포는 별도 승인 대상이다.
5. 승인된 Git 대상은 `https://github.com/WooRung/lgd-minigame-proj.git`의 `origin/main`이다. 실제 변경 경로만 stage하고 staged diff 확인 후 커밋·push하며 원격 반영을 확인한다. push가 배포를 유발하는 연결이 있으면 먼저 배포 승인 범위를 확인한다.
6. 기본은 단일 에이전트이며 기능별 추가 리뷰 에이전트나 반복 검사를 붙이지 않는다. 실패·새 변경·미해결 위험이 있을 때만 해당 검증을 다시 실행한다.

## 완료 기준

GAMEPLAY와 PLAN E1~E4의 모든 필수 항목이 구현되고, 표적 코어/서버 테스트 및 각 게임 독립 2인·4인 실제 브라우저 검증, 필요한 타입·Biome·빌드·배포 번들 검증과 GitHub 반영이 끝나야 한다. 러너 무한 진행/데이터 정리와 팡팡 5단계·다수 적 비겹침을 직접 확인한다. 기존 기록 보존·새 규칙 분리·소유권/중복 방지 검증도 필수다.

승인·접근 부족으로 남는 작업은 필요한 사용자 행동과 함께 기록한다. 필수 로컬 검증/Git 반영이 빠진 상태는 Goal 완료가 아니다. 실제 Cloudflare 배포는 이 Goal의 실행 범위가 아니며 검토 가능한 SQL·설정·명령·복구 절차를 준비해 인계한다.

최종 보고에는 새 조작법, 실제 검증 결과, 마지막 커밋·push 상태, 남은 원격 작업과 한계를 간결히 쓴다. 공개 URL 성공과 로컬 배포 준비를 구분한다.
